Topic 1Classes, Objects and Encapsulation

Run: java -cp out Main 1 · Files: Product.java, Main.java

Class
A blueprint. It says what data (fields) and actions (methods) a thing has. VinylRecord is a class.
Object
A real thing made from the class with new. Each object has its own values.
Reference
A variable that points to an object. Two references can point to the same object.
Encapsulation
Keep fields private. Allow access only through public getters and setters, so the class can check values.
private
Only inside the same class.
default (no keyword)
Anywhere in the same package.
protected
Same package, plus child classes.
public
Everywhere.

Code to remember

Javaclass Book {
    private int price;                    // private field

    public int getPrice() { return price; }

    public void setPrice(int p) {
        if (p >= 0) price = p;            // setter checks the value
    }
}

Book b1 = new Book();
b1.setPrice(300);
Book b2 = b1;            // same object, NOT a copy
b2.setPrice(500);
b1.setPrice(-10);        // ignored by the check
System.out.println(b1.getPrice());
Output500

Likely questions

What is the difference between a class and an object?

A class is the blueprint, like the design of a house. An object is the actual house built from it. One class can make many objects.

Why do we make fields private?

So nobody can put wrong values directly. If price were public, anyone could write price = -500. With a setter we can reject it.

What happens with VinylRecord c = a;?

No new object is made. c and a point to the same object, so a change through c is seen through a. In our demo, c.setStock(99) makes a.getStock() print 99.

If we pass an object to a method and change it there, does the change stay?

Yes. The method gets a copy of the reference, but it points to the same object. Our addOneCopy(b) changes b's stock from 6 to 7.

Is Java pass-by-value or pass-by-reference?

Always pass-by-value. For objects, the value that is copied is the reference. So the method can change the object's fields, but it can not make the caller's variable point to a different object.

What are the default values of fields?

int → 0, double → 0.0, boolean → false, char → '\u0000', and any object (like String) → null. Local variables have no default; you must give them a value.

In our project: Product has private String name and private double price, protected int stock, and a package-private category. setPrice() throws InvalidPriceException for negative prices.

Topic 2Constructors and Method Overloading

Run: java -cp out Main 2 · Files: VinylRecord.java, Track.java

Constructor
A special method with the same name as the class and no return type. It runs automatically when you write new.
Default constructor
If you write NO constructor, Java adds an empty one for you. Track has none, so Java adds Track() { }.
No-arg constructor
A constructor you write that takes no parameters.
Parameterized
A constructor that takes values, like VinylRecord(name, artist, price, stock).
Copy constructor
Takes another object of the same class and copies its values into a new object.
this
Means "this current object". this.price = price sets the field from the parameter.
this(...)
Calls another constructor of the same class. It must be the first line.
Overloading
Same method name, different parameters (number, type or order). Java picks one at compile time.
Widening
If no exact match exists, Java automatically makes a small type bigger: byte → short → int → long → float → double, and char → int.

Code to remember

Javaclass Box {
    int w, h;

    Box() {                       // no-arg
        this(1, 1);               // calls the 2-arg constructor first
        System.out.println("no-arg");
    }
    Box(int w, int h) {           // parameterized
        this.w = w;
        this.h = h;
        System.out.println("two-arg");
    }
    Box(Box other) {              // copy constructor
        this(other.w, other.h);
    }
}

new Box();

Likely questions

How is a constructor different from a method?

A constructor has the same name as the class, has no return type (not even void), and runs automatically with new. A method has any name, has a return type, and runs only when you call it.

When does Java give a default constructor?

Only when the class has no constructor at all. It sets fields to their default values (0, null, false).

What is constructor chaining?

One constructor calling another with this(...) in the same class, or the parent's with super(...). In our VinylRecord(), the no-arg constructor calls this("Untitled Album", "Unknown Artist", 0, 0).

Can we use this() and super() in the same constructor?

No. Both must be the first line, and only one thing can be first.

Can two methods differ only by return type?

No, that is a compile error. Overloaded methods must differ in their parameters.

What is our overloading example?

restock(int quantity) and restock(int quantity, String supplier) in VinylRecord. Java picks one by the number of arguments.

Why does show('A') print 65?

There is no show(char). Java widens the char to an int, and the character code of 'A' is 65.

Topic 3Static Members and Nested Classes

Run: java -cp out Main 3 · Files: Product.java, Store.java

static variable
One copy for the whole class, shared by every object. Product.productCount counts all products.
instance variable
Each object has its own copy, like name and price.
static method
Called on the class: Product.storeInfo(). It can not use this or instance variables directly.
static block
static { ... } runs only once, when the class is first loaded.
instance block
{ ... } runs every time an object is made, just before the constructor body.
static nested class
A class inside a class, marked static. No outer object needed: new Store.Receipt(...).
inner class
A non-static class inside a class. It needs an outer object: store.new Cart(). It can use the outer class's fields.
anonymous class
A class with no name, written and used in one place, usually to implement an interface.
Singleton
A class that allows only one object. Private constructor + static getInstance().

Likely questions

What is the order: static block, instance block, constructor?

The static block runs first and only once, when the class loads. Then for every new: the instance block, then the constructor body.

Why can't a static method use instance variables?

A static method belongs to the class and can run without any object. With no object, there is no name or price to use.

Static nested class vs inner class?

Static nested: no outer object needed, and it can only use the outer class's static members directly. Inner: needs an outer object (store.new Cart()) and can use all outer fields, even private ones. Our Cart prints storeName, a private field of Store.

How do you make a Singleton?

Three steps: a private constructor, a private static variable that holds the one object, and a public static getInstance() that creates the object the first time and returns the same one every time after.

Where did we use an anonymous class?

In topic 3: Playable radio = new Playable() { public void play() {...} }; It implements the interface without making a new named class file.

Can a static method be overridden?

No. If a child writes a static method with the same name, it hides the parent's one. That is covered in Topic 5.

Topic 4Inheritance

Run: java -cp out Main 4 · Files: VinylRecord.java, LimitedEdition.java, Cassette.java

Inheritance
A child class gets the fields and methods of a parent with extends. It is an "is-a" relation: a VinylRecord is a Product.
Single
One parent, one child: VinylRecord extends Product.
Multilevel
A chain: LimitedEdition → VinylRecord → Product.
Hierarchical
One parent, many children: VinylRecord and Cassette both extend Product.
Multiple (interfaces)
A class can not extend two classes, but it can implement many interfaces: VinylRecord implements Playable, Discountable.
super
Means the parent. super(...) calls the parent constructor; super.play() calls the parent's method.
final method
Children can use it but can not override it. Ours is getStoreName().

Likely questions

Why doesn't Java allow multiple inheritance with classes?

If two parents had the same method, Java would not know which one to use. This is called the diamond problem. Interfaces avoid it, so a class can implement many.

In what order do constructors run?

Parent first, then child. Run topic 4: it prints Product, then VinylRecord, then LimitedEdition, because each constructor's first line is super(...).

Are private members inherited?

They exist inside the child object, but the child can not use them directly. It uses the public getters instead. That is why VinylRecord calls getName() but uses stock directly, since stock is protected.

Are constructors inherited?

No. The child calls them with super(...).

What does final mean on a class, method and variable?

A final class can not be extended. A final method can not be overridden. A final variable can not be changed after it is set.

Show multilevel inheritance in our project.

LimitedEdition extends VinylRecord, and VinylRecord extends Product. So a LimitedEdition object can call getName() from Product and restock() from VinylRecord.

Topic 5Polymorphism

Run: java -cp out Main 5 · Files: Main.java (topic5)

Polymorphism
"Many forms". One method call can behave differently depending on the object.
Compile-time
Overloading. Java decides which method to call while compiling, from the arguments.
Runtime
Overriding. Java decides while running, from the actual object.
Overriding
A child writes the same method (same name and parameters) as the parent, with a new body.
@Override
Asks the compiler to check that you really are overriding. A typo becomes an error instead of a silent new method.
Upcasting
Product p = new VinylRecord(...): a parent reference holding a child object. Automatic.
Downcasting
VinylRecord v = (VinylRecord) p: back to the child type. Needs a cast; check with instanceof first.

Likely questions

Overloading vs overriding?

Overloading: same name, different parameters, in the same class, decided at compile time. Overriding: same name and same parameters, in parent and child, decided at run time.

What is runtime polymorphism in our project?

In topic 5 we loop over Product[] shelf and call showDetails(). The same line prints "Vinyl", "Cassette" or "Limited Edition Vinyl", because each object uses its own getType().

Why does p.category print "Product" but p.getType() print "Vinyl"?

Variables are not overridden. Java uses the reference type (Product) for variables. Methods are overridden, so Java uses the real object (VinylRecord).

When do we get ClassCastException?

When we downcast to the wrong type. p is really a VinylRecord, so (Cassette) p fails at run time. Checking with instanceof first prevents this.

Which methods can not be overridden?

static methods (they are hidden instead), final methods, and private methods (the child can't see them). Constructors also can't be overridden.

Can an overriding method make access weaker, for example public to private?

No. It can keep the same access or make it wider, but never narrower.

Likely questions

Why can an abstract class have a constructor if we can't create it?

The child calls it with super(...) to set up the shared fields. Our Product constructor sets name, price and stock for every child.

Can an abstract class have no abstract methods?

Yes. Marking it abstract simply stops people from creating objects of it.

What if a child does not write the abstract method?

Compile error, unless the child is also declared abstract.

Why did we make Product abstract?

The shop never sells a plain "product". It sells a vinyl or a cassette. Product only holds the shared parts, and getType() has no sensible answer at that level.

What is a "common workflow" in an abstract class?

A normal method that does the same steps for everyone and calls an abstract method for the part that differs. Our showDetails() is written once in Product and calls getType(), which each child fills in.

Show an interface reference in our project.

Playable[] players = { vinyl, cassette }, then pl.play() plays each one its own way, and pl.stop() uses the default method.

Topic 7Arrays and Collections

Run: java -cp out Main 7 · Files: Main.java (topic7), Store.java

Array
Fixed size, set when created: new Track[3]. That creates 3 empty (null) slots, not 3 objects.
ArrayList
A list that grows by itself. Fast for get(index).
LinkedList
A list of linked nodes. Fast to add or remove at the two ends, so it works well as a queue.
Generics
ArrayList<String> allows only Strings. Mistakes are caught at compile time, and no casting is needed.
Iterator
Walks forward with hasNext() and next(). remove() deletes safely while walking.
ListIterator
Walks both ways (hasPrevious(), previous()) and can set() and add().
Queue
First in, first out. offer() joins the back, peek() looks at the front, poll() takes from the front.

Likely questions

Array vs ArrayList?

An array has a fixed size and can hold primitives like int. An ArrayList grows by itself and holds only objects (it uses Integer, not int).

ArrayList vs LinkedList?

ArrayList is faster for reading by index. LinkedList is faster for adding and removing at the start or end, which is why we used it for the order queue.

peek() vs poll()?

Both return the front item. peek() leaves it in the queue; poll() removes it. On an empty queue both return null.

What is the benefit of generics?

Type safety. albums.add(25) on an ArrayList<String> fails at compile time, and we never need to cast when we take items out.

Iterator vs ListIterator?

Iterator works on any collection, goes forward only, and can remove. ListIterator works on lists, goes forward and backward, and can also set() and add().

If two array variables point to one array and we change an element, what happens?

Both see the change, because there is only one array. In topic 7, changing sameArray[0].title also changes tracks[0].title.

Topic 8Exception Handling

Run: java -cp out Main 8 · Files: OutOfStockException.java, InvalidPriceException.java, Main.java (topic8)

Exception
An error while the program runs that stops the normal flow, like dividing by zero.
Hierarchy
Throwable → Error (serious, don't catch) and Exception → RuntimeException (unchecked) and others (checked).
Checked
Java forces you to handle it at compile time. Example: IOException, and our OutOfStockException.
Unchecked
Extends RuntimeException; not forced. Examples: ArithmeticException, NullPointerException, our InvalidPriceException.
try / catch / finally
try holds risky code; catch handles the problem; finally always runs, error or not.
throw
Actually throws one exception object: throw new OutOfStockException("...").
throws
Written on the method to warn callers: void sell(int q) throws OutOfStockException.
Propagation
If a method doesn't catch an exception, it goes up to the method that called it, and so on.

Likely questions

Checked vs unchecked?

Checked exceptions extend Exception, and the compiler forces you to catch them or write throws. Unchecked ones extend RuntimeException and are not forced. Ours: OutOfStockException is checked, InvalidPriceException is unchecked.

throw vs throws?

throw is a statement inside a method that throws one exception. throws is in the method heading and lists the exceptions it might throw.

Does finally always run?

Yes: after normal flow, after a catch, and even after a return in try. The only common exception is System.exit().

What if both try and finally have a return?

The value from finally wins and replaces the one from try. This is why returning from finally is bad practice.

What happens if an exception is thrown inside a catch block?

The finally of that try still runs, and the new exception goes out to an outer try/catch. Our topic 8 nested example shows: inner catch, inner finally, outer catch.

Explain propagation with our example.

methodC reads index 5 of a 2-item array and throws. methodC has no catch, so it goes to methodB. methodB has none either, so it goes to methodA, which catches it.

How do you make your own exception?

Make a class that extends Exception (checked) or RuntimeException (unchecked), and pass the message to super(message).
